** Testing view **
Tests are listed in the built-in Testing view under the ExTester test controller
    - no custom activity bar container, no UI Tests view, no CodeLens
Folders that contain test files matching testFileGlob are listed, then files, describe blocks and it tests
    - Mocha's TDD interface works too: suite and test instead of describe and it (the file is read as BDD when it calls a BDD function)
    - context, specify, xdescribe, xcontext, xit and xspecify are listed; the x functions show as skipped
    - if describe or it has variable (like ${foo}) inside name, this variable is processed as string
    - a file that cannot be parsed is shown without children and the error is logged
Tests marked with .only or .skip show only / skip as description, files that contain .only show .only
Own or inherited .only / .skip are tags: filter @extesterRunner:only and @extesterRunner:skip shows only them
Clicking on file, describe or it opens editor on line of occurrence
New file matching pattern is created, tree will update itself
File matching pattern is deleted, tree will update itself
File matching pattern is changed, tree will update itself
Changing runner settings or extester.config.json updates the tree
Refresh Tests in the Testing view updates the tree manually
Run button on the ExTester root, a workspace folder, a folder, a file, a describe or an it runs only that part
    - describe and it run the file with MOCHA_GREP
Gutter buttons next to each describe and it run that block, right-click offers Debug Test
Test: Run Tests in Current File, Test: Rerun Last Run and run history work
Debug profile runs the same command in a JavaScript Debug Terminal, breakpoints in tests stop
    - Mocha timeouts are off unless the test sets this.timeout()
    - the debug run ends by itself when the test command ends (no Stop needed)
Each test shows passed, failed or skipped with duration
Failure shows error, expected/actual diff, clickable stack trace and screenshot thumbnail
    - Open Screenshot in the failure view opens the full image
Test Results shows the output of the run and of each test
Run that fails before any test (preRunTask fails, extest missing, invalid config) marks tests errored with the reason
Only one run at a time, starting another offers to stop the current one
Stop button of the Testing view stops the run in progress
preRunTask setting runs a VS Code task before each run; tests do not start when it fails or is missing
env setting passes environment variables to test runs; only names are logged
runCommand setting replaces npx extest setup-and-run; ${target} is replaced by the quoted target or appended
hiddenWindow setting (experimental) sets EXTESTER_HIDDEN_WINDOW=true, the test VS Code window is never shown or focused
    - a value of EXTESTER_HIDDEN_WINDOW in env wins
Screenshots and Logs views are in the Testing sidebar below the test tree, collapsed by default
Empty Screenshots and Logs views show welcome content with a link to the Temp Folder setting
virtualDisplay setting (Linux) runs tests on an Xvfb display started by the Runner, reused across runs; missing Xvfb fails the run with an install hint

** Logs view **
Folder structure from logs is available inside
    - all folders are listed
    - empty folders don't have expand button
    - if no folder nor file is available, welcome content explains why and links to the Temp Folder setting
Folders are sorted newest-first (by mtime)
Timestamp-named folders (YYYY-MM-DD_HH-mm-ss) display a human-readable label with raw name as description
Clicking on filename opens file in editor on line 0
If new file/folder is created, explorer will update itself
If file/folder is deleted, explorer will update itself
If file/folder is changed, explorer will update itself
Clicking on Refresh button will update explorer manually
Reveal in File Explorer button (folder-opened icon) opens logs directory in OS file manager
    - if directory doesn't exist, info message is shown
Clear Logs button (trash icon) removes all content from logs directory after confirmation
    - confirmation dialog is shown before deletion
Trash icon is available per-item on hover
    - click deletes that specific file or folder (with confirmation)
Right-click on item shows context menu with Delete and Reveal in File Explorer options
Collapse All button is available
    - if no folder nor file is present, button is not clickable [TODO]

** Settings ** 
Settings are split into three categories - View, Command Line and Logs
Values from the runner section of extester.config.json beat user settings, workspace settings beat the file
View settings:
    Exclude glob is excluding path from test file search
    Ignore Path Part removes part of string from folders (/src/test/abcd can be presented as abcd only)
    Test File Glob specifies prescription for file searching
Command Line Settings:
    Run Sources:
        - when active, test sources are passed to setup-and-run as they are (Out and Root folders are ignored)
        - requires ExTester 8.29.0+ and tsx resolvable from the first workspace folder (checked by ExTester, not by Runner!)
    Adding additional args will add this arguments to setup-and-run command
        - they're added "as it is" so it's recommended to add single quotes to paths
    Out folder is used for test execution
        - value is used to create path for running tests
        - 'out' is default value
    Root folder specifies root directory
        - may be undefined
        - basically it's the part removed from path of .ts file while creating output .js path
    Temp Folder: 
        - if empty, default TMP_DIR location is used
        - if env. variable is set, then it's used (but this part is handled by ExTester, not by Runner!)
        - if there's path, then it's used
    VS Code type changes type used for execution
    VS Code version changes version used for execution
    Config File points to extester.config.json in a subfolder and is passed with --config
    Env passes environment variables to test runs, only names are logged
    Pre-Run Task runs a VS Code task before each run
    Run Command replaces npx extest setup-and-run (version, type, temp folder, additionalArgs are not added)
    Hidden Window (experimental) sets EXTESTER_HIDDEN_WINDOW=true for the run (VS Code 1.147+)
Logs View settings:
    Hide Empty Log Folders:
        - when active, only folders with content are showed in Logs view
